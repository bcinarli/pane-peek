# PanePeek

A focused local file browser for macOS 26+, with independent directory panes and a Details sidebar for image/video previews and text editing.

The application lists directories in one or two independent panes beside Details. The joined One Pane / Two Panes toolbar toggle shows a square and split-square icon beside its labels. It and the View menu keep the active browser visible while preserving the other browser's directory, selection, settings and scroll position. Returning to Two Panes keeps the current browser on the left and restores the other on the right. Layout changes retain the current editor and do not prompt about unsaved changes. Navigate with Home, root/ancestor breadcrumbs, directory double-click or Command-Down, Go to Folder/Command-L, and the shared folder chooser or Enclosing Folder action (Command-Up). Long breadcrumbs scroll horizontally; directory links follow their canonical target. Rows use Name / Size / Modified columns. File sizes use compact decimal units; directories, packages and unavailable sizes show `-`, with no recursive totals. Exact file bytes remain available in help/accessibility. Click each pane's Name, Size or Modified heading to sort; click again to reverse. Size starts largest first and orders byte counts numerically, with directories and unknown sizes last in either direction. Name keeps folders first; Modified sorts folders and files together by date. URL selections stay intact through reordering. Command-click toggles rows, Shift-click selects a range, and Edit → Select All (Command-A) selects visible rows. Escape closes an open Quick Look preview, cancels an inline rename, or clears the focused listing when neither is active. Details shows the primary selected name and full absolute path, with an adjacent copy action. Rows show relative recent dates or exact older dates, with complete timestamps in help/accessibility, and distinguish packages/links. File icons identify source code, configuration, images, video, audio, archives, spreadsheets, documents and text, with a generic icon for unknown types. Classification uses filenames and macOS type information without reading file contents. Hidden items keep their type icon and show a small eye-off badge; their accessibility/help description includes Hidden. Directory actions and the View menu offer Show Hidden Files (Command-Shift-period) and Refresh (Command-R) for the focused pane. Visibility and sorting survive navigation and Refresh. Failed reads keep the previous directory usable. Move and Trash support selected items. The bundle uses the accepted peeking-P development icon.

Details reads creation/modified dates, Unix permissions, owner/group, type and available byte size for the focused pane's primary item. Unavailable fields are explicit; folders and packages have no aggregate size. Links show their own metadata and stored target path separately, including broken links. Selection changes and successful Refresh reload metadata; failed reads clear previous values and show an error. Metadata remains visible while content preview is unavailable.

With a browser selection, press Space to toggle a separate native Quick Look window. It previews saved files using macOS support, including images, PDFs and video; Escape closes it without clearing the selection. Multiple selections use displayed order and start at the primary item. Up/Down follows the browser selection when the preview does not consume those keys. The preview follows the active browser/window and closes when its selection is empty. Editor and rename typing keep their normal Space behaviour. Quick Look leaves unsaved Details text in memory and previews the saved disk version.

Resize the whole Details column with its divider. Expand/Restore in the Details header and View menu requests half the content width, subject to the visible browsers' minimum widths, then returns to the previous preferred width. Narrow windows temporarily clamp that preference. View → Make Details Wider/Narrower adjusts the visible width in 10-point steps (Control-Command-Left/Right). Entering Edit keeps the chosen width. Preview/Edit fills the height left after other Details content; short windows and long metadata remain scrollable.

Details shows read-only image previews above metadata for image filenames recognised by macOS and formats supported by its image decoder. Images fit the preview area without distortion and respect stored orientation; animated images show a still frame. Image links preview their target while retaining their own metadata and listed path. Preview accepts files up to 32 MiB and 64 million source pixels, downsampling to at most 2048 pixels per side. Decoding runs one image at a time in the background; selection/Refresh changes discard stale results. Corrupt, unsupported, unavailable and oversized images show a message while file information remains available. Images have no Edit or Save controls.

Details also previews self-contained local videos supported by macOS. Each selection or Refresh starts paused at the beginning, with native Play/Pause, timeline and playback controls. Video fits the available area without distortion. Video links retain their own metadata and listed path. Replacing or clearing the selection, removing the preview or closing its window stops playback and releases the player. Corrupt, missing, protected, unsupported and audio-only files show a fallback while file information remains available. Videos have no text-edit or Save controls.

Above metadata, Details previews UTF-8 text with or without a BOM, up to 1 MiB including the BOM. Text is selectable, copyable and read-only. Empty files, NUL-containing binary files, invalid UTF-8, oversized files, folders/packages and read errors have explicit states. File links can preview regular text targets while retaining their listed path and own metadata. Refresh rereads the selected file, including when its size and timestamp have not changed. The preview uses installed Operator Mono Lig, then JetBrains Mono, then the system monospaced font. Fonts are optional and are not bundled. Swift, JSON, YAML/YML, TOML, JavaScript/TypeScript, HTML/XML, JSX/TSX, CSS/SCSS, PHP, Go, Rust, Java, Python, Markdown, Shell/Bash/Zsh, SQL, C/C++, C#, Dockerfile and Makefile previews have lexical highlighting with light/dark colours. JavaScript includes `.js`/`.mjs`/`.cjs`; TypeScript includes `.ts`/`.mts`/`.cts`; HTML includes `.html`/`.htm`. Markup remains source text; HTML script/style bodies stay plain. JSX/TSX distinguish tags, attributes and embedded code expressions while preserving plain child text and literal entities. CSS/SCSS colour selectors, properties, values and comments; SCSS also colours variables and directives. PHP highlights standard blocks, variables, strings and comments; surrounding markup and configuration-dependent `<?` tags stay plain. Go colours keywords, quoted/raw strings, runes, comments and numeric forms. Rust adds `.rs` keywords, strings/characters, lifetimes, nested comments and numbers. Java adds `.java` keywords, strings/characters, text blocks, comments and numbers, retaining original Unicode escapes in the displayed source. Python adds `.py` keywords, quoted/raw/byte/triple/formatted/template strings, comments and numbers. Markdown `.md` colours headings, emphasis, links and inline/fenced code while retaining source text. Shell colours reserved words, quoted strings, comments, parameters and heredocs in `.sh`/`.bash`/`.zsh` and common startup files such as `.bashrc` and `.zshrc`. SQL `.sql` colours keywords, quoted strings/identifiers, parameters and nested comments, including PostgreSQL dollar strings. C/C++ source/header files colour keywords, strings/raw strings, comments and preprocessor directives. C# `.cs` adds keywords, quoted/verbatim/interpolated/raw strings, characters and comments. Dockerfile, Dockerfile.* and .dockerfile variants colour instructions, quoted values, variables, line comments and heredocs. Makefile variants colour targets, assignment names, directives, references, quoted values, comments and literal define bodies. Indented `.sass` stays plain. Other extensions stay plain. Preview/Edit now shares this highlighting pipeline. T07 keeps edits in memory until explicit Save, shows Unsaved, and offers Save/Discard/Cancel before replacing a draft. Empty supported text is editable; file links and unavailable content stay read-only. Save uses atomic replacement, preserves UTF-8 BOM/newlines/Unix permissions and rejects changed, replaced or missing files. Errors retain the draft. Simultaneous external writes during saving remain an MVP limitation.

New Text File (Command-Option-N) and New Folder (Command-Shift-N) are available in the File menu, Directory actions and pane background menus. Enter the exact name, including any desired extension. Creation rejects invalid names and occupied destinations, including broken links, and selects the new empty item. New text is immediately editable. Dot-prefixed creation enables Show Hidden Files only in its creating pane. Other matching panes refresh while preserving their own settings and selection. Dirty drafts use Save/Discard/Cancel before the name prompt; failures remain visible. The [creation review fixture](agent-paper-trail/specs/001-mvp/evidence/new-text-file-folder.md#disposable-fixture-and-run-instructions) provides disposable checks.

Rename one selected file, folder, package or link with Return in the browser list, a file-row double-click, its row context menu or File → Rename (Command-Shift-R). Edit the name inline; Return confirms and Escape cancels with selection retained. The basename is initially selected without its final extension; folders and extensionless dotfiles are selected whole. The extension remains editable. Rename keeps the item in its containing directory. Invalid names and occupied destinations are rejected; case-only renames follow the filesystem. Affected dirty documents use Save/Discard/Cancel before mutation. Cancel or failure retains the draft; Discard takes effect only after successful rename. Matching panes refresh, browsers inside a renamed directory follow the new path, and affected previews reload or close with a fresh save baseline. Renaming a link retains its target text. Rename keeps each pane’s hidden visibility setting. The [rename review fixture](agent-paper-trail/specs/001-mvp/evidence/rename-affected-document-handling.md#disposable-fixture-and-run-instructions) provides disposable checks. Cross-window mutation coordination remains a later task.

Drag local files, folders, packages or listed links from Finder onto a visible browser to copy them into its current directory. Hold Command to request a move when the source permits it; it executes directly using the captured sources and destination. Whole selections use the same preflight, dirty-document guards, partial outcomes and refresh as context transfers. Single-pane mode accepts Finder drops. Unsupported payloads and service URLs are rejected. Application status reports the actual filesystem outcome after processing the accepted drop. Selected PanePeek rows also drag between panes or to Finder. Affected unsaved files or folder/package descendants prompt before export; after Save/Discard, drag again to start. Cancel or failed Save exports nothing. Source edits and context mutations are locked during the drag; an aborted drag releases the lock. Finder controls outgoing filesystem behaviour, so Refresh after an external change. The [drag fixture and manual checklist](agent-paper-trail/specs/001-mvp/evidence/drag-and-drop-finder.md) provide disposable review steps.

Select files, folders, packages or symlinks and choose Copy to Other Pane from the row context menu. Shift-F10 opens the row menu from the focused list (Fn may be needed). The other pane must be visible. Copy captures the selection in displayed order and its destination before work starts. It preflights every item, rejects the whole request on a known name or folder ancestry conflict, and leaves sources intact. Navigate or change browser modes while copying; later navigation does not redirect the captured request. Affected dirty documents use Save/Discard/Cancel first. Execution stops on the first failure and reports completed destination paths, the failed item and unattempted sources. Completed copies remain in place; a failed copy may leave a destination item that needs inspection. Compact toasts show progress and results. Successes name the file (or count for a batch) and disappear after five seconds, with no details action. Errors and partial failures remain until dismissed; their details button opens the complete result and paths. The [copy review fixture](agent-paper-trail/specs/001-mvp/evidence/copy-to-other-pane.md#disposable-fixture-and-run-instructions) provides disposable checks.

Select files, folders, packages or listed links and choose Move to Other Pane from the row context menu to move immediately. It captures the selection in displayed order and the other browser’s destination before asynchronous work or dirty-document choices. Move requires two visible browsers and preflights every item before mutation. If a destination name exists, Keep Both suggests an unused numbered name before the file/package extension; folder names are numbered as a whole. Edit that name if needed. Invalid, occupied and batch-reserved names show an error and retry. Resolve all known collisions before any item moves; Cancel aborts the whole move batch. Same-item, duplicate-input and ancestry conflicts remain rejected, and a late collision never silently overwrites. Regular-file collisions also offer Replace. It protects source and destination drafts and retains the previous destination until the transfer succeeds. A failure restores that file when the destination is still free; otherwise the result identifies its retained recovery path. Folders, packages and links offer Keep Both or Cancel, without merging. Execution stops on the first failure, retaining completed moves and reporting failed/unattempted sources. Affected drafts use Save/Discard/Cancel before any item moves; a failed or unattempted dirty item retains its edits. Successful moves close or reload affected previews with fresh Save identities and follow browsers inside a moved folder. Failed cross-volume copies retain the source; failed removal can leave a complete destination and a partly removed source folder, with both paths reported. Cleanup failures identify retained temporary copies; an item removed before cleanup failed still updates the browsers and preview. Results use the same toasts, with incomplete transfers and recovery details retained until dismissed. The [batch move review fixture](agent-paper-trail/specs/001-mvp/evidence/move-to-other-pane.md#unit-2-disposable-fixture) records checks and acceptance, with individual native/accessibility and real-volume outcomes unreported. Cross-window coordination remains T16.

Move to Trash is available in the row context menu and File menu for selected files, folders, packages and listed links. It captures the selected items in displayed order and proceeds directly without a routine confirmation. Affected edits use Save/Discard/Cancel before any item is trashed; Cancel or a failed Save aborts the batch. Every source is revalidated before the first mutation. Execution stops at the first failure and reports completed, failed and unattempted paths without rolling back earlier successes. Failed or unattempted dirty items retain their drafts; actually removed sources close affected previews and reconcile panes. Browsers inside a trashed folder recover to an accessible parent. Trash failures remain visible and never fall back to permanent deletion. The [Trash review fixture](agent-paper-trail/specs/001-mvp/evidence/delete-to-trash.md#unit-2-disposable-fixture) provides disposable checks. Both units are accepted; individual native/accessibility outcomes remain unreported. Cross-window coordination remains T16.

Right-click an item and choose Reveal in Finder to open directory contents or reveal/select files, packages and file links in their containing folders. The same context menu offers absolute/relative path copying. It applies to the selection and is also available in the File menu, disabled when nothing is selected. It retains PanePeek's document and reports detected errors. An unselected row becomes selected; a selected row preserves the selection and becomes primary. Multiple paths copy one per line in displayed order, preserving plain spaces, Unicode and listed link paths. Relative paths use that pane's directory. The Edit menu also offers Copy Absolute Path (Command-Option-C) and Copy Relative Path (Command-Option-Shift-C). Directory actions and Go → Copy Directory Path copy the focused directory, including with no selection.

Each pane's breadcrumb star saves or removes its displayed directory without changing pane focus, navigation or selection. Both panes reflect the same saved paths. The toolbar Favourites button opens a popup with each folder name above its subdued, wrapping full path. Search filters folder names and full paths, ignoring case and accents; clearing it restores the saved list. The header/search stay above a scrolling list with room for roughly six to eight typical rows; wrapped paths and larger text can reduce that count. Each row has separate open-in-active-pane and remove-favourite icons; Close, Escape and outside click dismiss the popup. The menu-bar Favourites menu retains keyboard access to opening and its Remove Favourite submenu. Removal handles any saved entry, including a deleted or inaccessible directory, without opening it or changing panes and drafts. Favourites and explicit removals persist locally across launches; an unavailable favourite reports the normal navigation error and remains saved until removed. Directory links use the canonical location already displayed by navigation. Dirty favourite navigation follows the same Save/Discard/Cancel guard; stars and removal retain drafts. Favourites are shared across windows.

Initial launch, Command-Q relaunch and Dock reopening after the final window closes restore the most recently active window's directory pair, presentation order, One Pane/Two Panes mode, active browser, preferred Details width, expanded Details state, browser pane proportions and window size/position. Restore Previous Width retains the underlying preference after reopening. Missing directories fall back independently to home with a visible status message. Explicit File → New Window starts two browsers at home with compact Details, even with no windows open. Selection, sorting, hidden visibility and unsaved buffers are not restored. [T17 correction evidence](agent-paper-trail/specs/001-mvp/evidence/window-reopen-restoration.md) records overall acceptance and remaining individual checks. Window placement is fitted to available screens after display changes; native browser minimums preserve the saved proportion for widening again.

## Build and run

Requirements: macOS 26+, Swift 6.2 or later with a macOS SDK supporting the deployment target, Node.js 22 or later, and full Xcode with its licence accepted for app bundling. The Swift package and behaviour tests can use Command Line Tools. UI icons are bundled locally; the app has no runtime third-party dependencies.

From the repository root:

```sh
node scripts/build-app.mjs
open .build/PanePeek.app
```

The script builds the debug executable and creates a local app bundle in `.build/PanePeek.app`, including the development icon, compiled UI icons and light/dark accent colours. Its minimum macOS version comes from `Package.swift`. Quit the running app before rebuilding it. Generated build files are ignored by Git.

The bundler uses the same Xcode environment for Swift compilation, package inspection and asset compilation. It respects `DEVELOPER_DIR` or the selected Xcode installation. If Command Line Tools are selected and `DEVELOPER_DIR` is unset, the script uses `/Applications/Xcode.app/Contents/Developer` for the entire build. For a different Xcode location, set `DEVELOPER_DIR` when building; the script does not change global toolchain selection.

The local development bundle runs outside the App Sandbox. Distribution signing and notarisation are deferred.

If a rebuilt bundle fails to relaunch with an invalid cached executable signature, use the [generated-executable recovery](agent-paper-trail/notes/0001-build-and-bundle.md#rebuilt-executable-recovery). No signing identity or system setting is changed.

## Tests

Run the browsing, sorting, visibility, selection, copied-path, favourites, metadata, preview, editor, creation, rename, copy, move and highlighting behaviour suite:

```sh
node scripts/test.mjs
```

The runner uses `swift test`, adding the installed Testing macro search directory when available. Tests use isolated temporary directories, uniquely named preference suites and tiny generated video/audio-only resources; completion-order tests use controlled asynchronous reads and sorts. They do not mutate working files or the application's real preferences.

## Continuous integration

[CI](.github/workflows/ci.yml) runs the full test suite and builds the development app on macOS 26 Apple Silicon, using Xcode 26.6 and Node.js 24. It runs for every PR targeting `main`, pushes to `main` and manual requests. The stable check name is `macOS build and test`; keep it aligned with the required-check rule when editing the workflow.

Successful runs provide a `PanePeek-macos-arm64` artifact containing the zipped development app, retained for seven days. Download it from the run's **Artifacts** section and extract the outer artifact archive, then the app zip. The inner zip preserves executable permissions. The app is not distribution-signed or notarised.

## Structure

- `Package.swift` owns the macOS deployment target and application executable.
- `sources/panepeek/` contains the SwiftUI app entry point, native navigation controls, independent window lifecycle, restoration preferences and window layout.
- `sources/panepeek-core/` contains asynchronous directory listing and per-pane/window browsing state.
- `tests/panepeek-core/` contains the meaningful browsing behaviour tests.
- `scripts/build-app.mjs` builds and bundles the app using Swift and Node's built-in libraries.
- `assets/PanePeek.icns` is the development icon derived from the accepted SVG composition. To regenerate it, run `node scripts/export-app-icon.mjs`; this uses built-in macOS Quick Look, Swift/AppKit, `sips` and `iconutil`, with intermediate files in `.build/app-icon/`. The exporter preserves the SVG geometry and adds transparent margins and a rounded background. Final icon refinement and small-size acceptance remain in T18.
- [`assets/ui.xcassets`](assets/README.md) contains the draft's Lucide template icons and named Mauve accent. The bundler compiles it with Xcode's `actool` and includes the icon licence.

Swift target/module names keep their normal capitalisation. Explicit package paths allow lowercase source/test directories. The platform requires `Contents`, `MacOS` and `Resources` inside the app bundle.
