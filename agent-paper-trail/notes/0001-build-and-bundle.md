# Build and bundle notes

Status: Active

Source, test and asset directories use lowercase names with explicit package paths. Swift module/type names and platform-required bundle directories retain their standard case.

The [test runner](../../scripts/test.mjs) adds the installed Testing macro search directory when present; some Command Line Tools builders omit it. The UI's private `ViewState` alias selects SwiftUI's existing property wrapper on SDKs that also declare a `State` macro. These choices allow the Swift package to build/test with Command Line Tools. App bundling uses one full-Xcode environment for Swift compilation, package inspection and `actool`, avoiding the missing linker search paths generated by the Command Line Tools builder. It honours explicit `DEVELOPER_DIR` and leaves global selection unchanged; follow the [build requirements](../../README.md#build-and-run).

The Swift package executable acquires its development icon from the local app bundle: `CFBundleIconFile` names `Contents/Resources/PanePeek.icns`. Normal builds copy the checked-in asset; icon regeneration is a separate step using the accepted SVG composition and built-in macOS tools. [Build/run instructions](../../README.md#build-and-run) and [T01 evidence](../validation/t01-launchable-shell.md) own regeneration guidance. A resolved file icon does not prove every cached Dock/app-switcher presentation has refreshed.

## Rebuilt executable recovery

In-place replacement of a previously launched executable can leave macOS rejecting the rebuilt bundle with `Taskgated Invalid Signature`. A verified compiler output can still be rejected after replacing an already launched executable. A fresh generated executable has restored launch without signing changes; a cached signature is a possible cause, not a diagnosis for every signing failure.

Recovery applies only to local generated development output. Preserve the previous executable and replace it with fresh build output after quitting the app; do not apply this workaround to signed distribution packages or bypass security warnings. The [contributor guide](../../CONTRIBUTING.md#build-and-run) owns build commands.
