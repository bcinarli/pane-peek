# PanePeek MVP specification

PanePeek is a focused macOS file browser for Bilal’s local workflow. It supports one or two independent directory browsers with an inline text/image/video preview and text editor, allowing files to be inspected and moved without switching applications.

The [accepted browser UI and preview refinements](../../decisions/2026-10-16-browser-ui-and-preview-improvements.md) extend file icons, layout controls, favourites, previews and operation feedback. Their implementation and manual acceptance are tracked separately under T20.

The [additional file-preview decision](../../decisions/2026-10-20-additional-file-previews.md) extends the preview contract under A36–A39. These additions have separate implementation and acceptance gates.

## Requirements and proposed defaults

Requirements below define the current product contract; proposed details remain subject to review.

| Requirement | MVP outcome |
| --- | --- |
| R1 Independent panes | Toggle one/two-browser view, preserving independent directories, selection and settings, with clickable breadcrumbs and sorting. |
| R2 File transfers | Copy or move selected items between visible panes, including drag and drop; other-pane actions require two-pane mode. |
| R3 Inline preview and editing | Inspect text/code and metadata in a resizable Details column, expandable under A35's mode-dependent bounds; toggle Preview/Edit with syntax highlighting. |
| R4 Independent visibility | Toggle hidden files separately in each pane. |
| R5 Favourites | Save directories and open them in either pane. |
| R6 Paths and context actions | Keep the selected absolute path visible and copyable; copy absolute/relative paths from context menus and the focused directory path from shared actions. |
| R7 File management | Delete and rename items; create text files and directories. |
| R8 Windows and restoration | Use independent windows; restore the last active window’s directories, browser mode/active identity and preferred Details width on relaunch. |
| R9 GitHub release updates | Check for releases, download a DMG on request and open it for manual installation through a replaceable update component under A40. |

Product defaults:

- Support macOS 26 and later only, using SwiftUI with an AppKit text editor and Foundation file services. iPadOS and mobile designs/builds are outside the MVP scope.
- Allow multiple windows, each with two retained directory browsers, a one/two-pane mode and resizable Details at the far right. Start fresh windows in one-pane mode with expanded Details. The selected item’s preview is at the top of the sidebar, with file metadata below. A toggle switches supported text between preview and editor. The most recently activated pane in that window supplies the selection.
- Support multiple selection using Command-click, Shift-click and Select All. Copy to Other Pane / Move to Other Pane operate on the selection when both browsers are visible. Include drag and drop between visible panes/windows and interoperability with Finder.
- Relative paths are based on the directory displayed in the item’s pane. A file at `/example/project/src/main.swift` in a pane displaying `/example/project/src` yields `main.swift`.
- Supported images and videos have read-only previews in Details. Space opens the system Quick Look panel for selected items. Plain text and UTF-8 files up to 1 MiB are editable. The languages listed in A15 highlight in both Preview and Edit; other text stays editable without highlighting.
- Copies into their source folder use unused numbered names automatically. Other Copy/Move name collisions offer editable Keep Both, Cancel and explicit regular-file Replace. Folder merging and silent overwrites are deferred; invalid or late conflicts reject safely.
- Favourites and one remembered window configuration persist locally: its ordered directory pair, browser mode, active-browser identity and preferred Details width. Relaunch restores that configuration in the initial window; the first-ever launch retains two browsers at home, showing one beside expanded Details. Every explicitly opened new window uses those same fresh defaults. Remember the most recently active window, not all windows. Selection, sorting, hidden-file visibility and scroll position remain session state.
- Move and Trash execute without routine operation-confirmation dialogs; affected unsaved edits still follow Save / Discard / Cancel. Delete sends items to Trash; permanent deletion is deferred. Rename targets one item at a time. New Text File and New Folder create items in the active pane’s directory.
- Ordinary development builds run outside the App Sandbox. Production packages use the shared sandbox access model with channel-specific signing; App Store packaging and submission retain separate gates.

## Accepted UI design

The [Browse & peek reference and original logo](../../design/001-mvp/README.md) were accepted by Bilal on 2026-10-03. [Decision 0003](../../decisions/0003-ui-and-logo-direction.md) records the original alternatives; [the accepted layout decision](../../decisions/2026-10-11-browser-layout-modes-and-details-sizing.md) carries forward that appearance/logo direction and replaces the always-dual layout. These requirements guide native implementation:

- Offer One Pane / Two Panes as one visibly joined, mutually exclusive icon-and-text toggle in the shared toolbar, with equivalent View menu actions. One-pane mode keeps the active browser. Returning to two panes keeps that browser on the left and restores the preserved browser on the right, following A34.
- Keep Details beside the visible browser(s), with preview/editor above metadata and a visible absolute-path copy control. Its divider supports resizing; Expand / Restore is available in the Details header and View menu. Fresh windows start with expanded Details; Restore returns to the compact preferred width under A35.
- Preserve native window dragging from title text and empty title-bar background, and the configured title-bar double-click action. Toolbar and traffic-light controls retain their normal interaction.
- Follow system appearance, using native Mac surfaces in Light and [Macchiato surfaces in Dark](../../decisions/2026-10-18-dark-macchiato-surfaces-and-controls.md): Base `#24273A` panels/previews, Mantle `#1E2030` headers/Details and Crust `#181926` frame. Retain Mauve `#C6A0F6` dark accents with Base text on enabled filled controls; Light retains darker Mauve `#8255B6` and native control presentation. Adapt editor token colours for each appearance and retain native text/caret/selection contrast.
- Browser rows use a separate muted selection fill, a contrasting outline and readable selected text, with neutral inactive selection. Retain Mauve controls. The [accepted selection decision](../../decisions/2026-10-12-muted-browser-selection.md) defines the colour roles and public native drawing approach.
- Give each pane a compact breadcrumb row: Home before filesystem root `/`, then clickable path components, with a trailing favourite star. The draft's 44 px row is a guide; native text sizing and long paths must remain accessible. Align both panes' location rows and list headings when paths wrap.
- Indicate the focused pane with a thin Mauve underline below its location, visible even without a selection. Avoid visible Active/Left/Right labels and repeated per-pane ellipsis menus. Accessible control names must still distinguish the panes and communicate focus.
- Use one shared toolbar for Go to Folder, Favourites and directory actions, targeting the most recently focused directory pane even while the editor/toolbar has keyboard focus. Go to Folder and Command-L expose an editable absolute directory path. Shared actions include parent navigation, Refresh, hidden visibility and Copy Directory Path. Sort controls remain per pane.
- Align Name | Size | Modified headings with their row columns. Name, Size and Modified are clickable sort controls. Show file sizes from listing metadata and `-` for directories or unavailable sizes; do not scan directory contents to calculate totals. Show the current direction beside the active heading; no separate sort picker or direction button.
- The toolbar Favourites button opens an anchored popover. Each saved-directory row shows its folder name above a subdued, accessible full path, with separate open-in-active-pane and remove-favourite icon buttons. Search matches folder names and full paths. Keep the header/search fixed above scrolling results, sized for roughly six to eight typical rows where space allows. No separate removal section appears in the popover.
- The menu-bar Favourites menu uses folder names for both opening and removal. Add only enough parent-path context to distinguish duplicate folder names; keep `/` for filesystem root and expose full paths through help and accessibility. Preserve saved order.
- Show an outline star for an unsaved directory and a filled Mauve star for a saved one. Stars act on their own pane's displayed directory; opening a shared favourite acts on the focused pane. Do not add a permanent favourites column.
- Keep Copy/Move to Other Pane in file context menus and drag/drop. Do not add selection-triggered transfer buttons. Essential shared actions and context actions remain keyboard accessible.
- Keep syntax highlighting when switching supported text into Edit. The original peeking-P concept is the logo direction; production icon preparation and small-size validation remain pending.

The mockup is illustrative. Its sample files, carousel, appearance selector and preview-host reflow are design tooling. One/two-pane and Details sizing controls are product requirements under A34/A35; mockup interaction checks are not native acceptance evidence.

## Accessibility baseline

Accessibility is an app-wide requirement under the [accepted baseline decision](../../decisions/2026-10-11-native-accessibility-baseline.md). Follow Apple's [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) and [typography](https://developer.apple.com/design/human-interface-guidelines/typography) guidance. Use applicable [WCAG 2.2 Level A and AA criteria](https://www.w3.org/TR/WCAG22/) as the baseline, interpreted for native macOS software through [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/). Accessibility takes precedence over matching the draft's exact dimensions or colours.

- Prefer system fonts and semantic text styles; retain monospaced paths/code. Support text enlargement without losing content or actions. Aim for 200%, working with native platform resizing capabilities as described by WCAG2ICT; verify the actual mechanism and any platform limits. Font styles alone do not establish enlargement support.
- Check light/dark and selected/focused states against applicable contrast requirements: 4.5:1 for normal text, 3:1 for large text and essential non-text controls/state indicators, with the standard's exceptions. Use more than colour to convey essential state.
- Make functions keyboard operable, with logical focus order, visible unobscured focus and no keyboard traps. Provide single-pointer alternatives to dragging and adequate pointer targets where the relevant native criteria apply.
- Expose useful names, roles, values and state through macOS accessibility APIs. Verify VoiceOver navigation and announcements for loading, errors and important state changes. Honour relevant system accessibility settings, including increased contrast and reduced motion.

Each UI unit checks the criteria it affects and records evidence or pending outcomes in [task evidence and MVP validation](validation.md#accessibility-and-native-review). T18 reviews all applicable A/AA criteria and records applicability, failures and remaining gaps. Native-control choices and visual approval must be accompanied by executed accessibility checks.

## Current-folder search

**A41:** Search file and folder names beneath the active browser’s current folder using Unicode-aware, case-insensitive literal substrings. Preserve spaces; file-content search and persistent indexing are excluded.

- Run cancellable background traversal within the granted root. Skip package contents, symbolic-link traversal and hidden subtrees when hidden files are off. Reject superseded results; report inaccessible subfolders and the 100,000-item traversal limit.
- Keep session-only queries with retained browser identity through navigation, layout and focus changes. Preserve each browser’s sort and hidden-file settings. Empty query restores the ordinary listing.
- Show filenames with relative containing paths, result status and an explicit no-matches state. Open Containing Folder navigates to the selected result’s parent and selects it, clearing that browser’s query.
- Preserve file actions, guarded selection and dirty documents. Cancelled transitions and failed Save retain prior state. Successful creation reveals/selects the new item by clearing the creating browser’s search. If a successful rename stops matching, reveal/select it in its containing folder, clearing only the initiating browser’s query; preserve hidden-file visibility and newer requests.
- Place an icon-only search button after a compact Back/Forward pair in the shared toolbar. Activating it reveals and focuses the field; an active query stays visible, and an empty field collapses after losing focus. Retain native control targets, keyboard operation and history commands. Verify affected accessibility behaviour under the app-wide baseline.


## Scope boundaries

The MVP includes one/two-browser layouts and Details width expansion, directory navigation with clickable breadcrumbs, per-pane name/size/modified-time sorting, refreshing, multiple selection, copying/moving and drag and drop, a details sidebar with text preview/editor and file metadata, Markdown highlighting, favourites, path copying, deletion to Trash, rename, text-file/folder creation, multiple windows and restoration of the last active window’s directory pair and layout. Regular directories and files are supported. Symlinks are listed and transferred as links; navigating through a directory link uses the canonical target location, following Finder. macOS packages are treated as files rather than browsable directories.

The [Git and agent-worktree spec](../2026-10-27-git-worktrees/spec.md) extends this baseline with optional local read-only Git inspection, worktree-location browsing, per-pane branch/status information and unified text diffs. Its [plan](../2026-10-27-git-worktrees/plan.md) and [acceptance matrix](../2026-10-27-git-worktrees/validation.md) own implementation and validation. Git features depend on available Apple-provided tools; ordinary browsing/editing remains usable without them. Existing sandbox, network, editor and accessibility requirements remain binding.

Excluded: iPadOS/mobile builds, cloud accounts, FTP/SFTP, remote connection management, synchronisation, search indexing, tabs, batch rename, permanent deletion, automated bulk workflows, source-control mutations and worktree cleanup, document previews beyond the accepted text/Markdown/image/SVG/video/PDF/static-HTML scope and read-only Git diffs, graphical SVG editing, PDF editing, script-driven HTML, automatic remote preview resources, restoration of every prior window or unsaved buffers, and distribution infrastructure. Operations on a multiple-item selection are included.

Local-only means PanePeek keeps file processing on the Mac without uploading documents or paths. The [GitHub release-update decision](../../decisions/2026-10-24-github-release-updates.md) permits only the A40 update checks and requested downloads as an app-operated network feature, while carrying forward the WebKit capability needed for local SVG/HTML. Renderer policies still block remote preview resources and scripts. Paths exposed by macOS may be backed by OS-managed cloud storage or mounted volumes. The MVP does not promise offline availability or block those paths; OS failures must be surfaced. Strict volume restrictions would require a separate decision.

## User behaviour and acceptance criteria

### Directory panes

Each window owns its browsers, presentation order, one/two-pane mode, active-browser identity, preferred Details width and editor state. Each browser owns its directory, selected items, primary selected item, hidden-file setting, sort field/direction, scroll position and loading/error state. Browser identity is preserved when its displayed side changes. Shared favourites, File information visibility and restoration preferences belong to the application.

- **A1:** Navigate using a folder chooser, an editable absolute directory path through Go to Folder/Command-L, parent navigation, Home, clickable breadcrumbs and double-clicking a directory. Shared navigation actions target the focused pane; Home targets its own pane. Changing one pane leaves the other pane’s directory, selection and visibility unchanged. Focus remains visible with an empty selection.
  Back and Forward beside the shared toolbar title, and in Go with Command-[ / Command-], target the active browser even while editor or toolbar controls have focus. Each retained browser owns independent session-only history through layout changes; new/restored windows seed only their first successful location. Record successful distinct directory visits across ordinary navigation routes. Back/Forward move through that history; a new successful destination after Back clears Forward. Refresh, repeated canonical locations, failed/cancelled and superseded requests do not add visits or advance history. Unavailable destinations retain the usable location and show an error; retain A12 and sandbox access safeguards. A history permission choice must grant the intended destination rather than substitute an unrelated folder, retaining identity-checked bookmark resolution. Existing rename/move and Trash recovery align the current entry without adding visits; older historical URLs can become unavailable. History does not retain access grants or restore prior selections/scroll positions, and is not persisted across launches.
- **A2:** List Name | Size | Modified columns with recognisable file-category icons. File sizes use listing metadata; directory and unavailable sizes show `-` without recursive calculation. Distinguish directories, packages and symbolic links; unknown file types use a generic file icon. Hidden items retain their type icon with a small eye-off badge, aligned row names and Hidden in their accessible description/help. Use the same hidden metadata as A4. Default to folders first and natural name order ascending. Allow sorting by name, size or last-modified time in either direction under A30. Empty directories show an empty state.

  Modified labels use completed elapsed units: under one minute Just now; under one hour minutes; under thirteen hours one through twelve hours. Thereafter use Today/Yesterday for local calendar days, otherwise `dd.MM.yyyy HH:mm` in the local timezone. Exact timestamps remain available through help/accessibility. Update relative labels each minute and after wake without rereading or reordering the listing. Unavailable metadata retains an honest fallback; future values display their exact date without special workflows.
  Browser columns resize independently through their header dividers, retaining aligned headings/cells and the existing sort policy. Keep widths with each browser identity through navigation and layout changes, independently across windows; widths remain session-only. Minimum widths are Name 160 pt including the icon, Size 72 pt and Modified 120 pt. Overflow scrolls horizontally without reducing the 250 pt browser minimum or increasing the window minimum. View → Column Widths… provides keyboard and single-pointer adjustment for the browser active when the controls open. The controls retain that browser as their target when focus changes and close if it is hidden. Restore Defaults resets only that browser: Size 72 pt, Modified 136 pt and Name filling the available width above its minimum.

- **A3:** An inaccessible, deleted or invalid directory produces a visible error and leaves the last successful directory usable. Slow reads do not block UI interaction; an older listing result cannot replace a newer navigation result.
- **A4:** Each pane has its own hidden-file toggle. Respect dot-prefixed names and filesystem hidden metadata. Manual Refresh reloads a pane; transfers refresh both affected panes. Automatic filesystem watching is deferred.

### Copy and move

With a browser list focused, Edit > Copy / Command-C exports the selected file URLs. Paste / Command-V copies clipboard files into that browser's current directory; Move Item Here / Option-Command-V moves them there. Both receiving commands work in one/two-pane mode, across PanePeek windows and with Finder file URLs, using the existing transfer guards and captured destinations. Disable unsupported clipboard payloads and unavailable receiving panes. Text/rename fields retain their normal clipboard and editing shortcuts.

Command-X defers a file move until Command-V in a PanePeek receiving browser. The [Cut/Paste decision](../../decisions/2026-10-19-browser-file-cut-paste.md) defines session-local clipboard ownership, cancellation and partial outcomes. Clipboard replacement or a new Copy cancels pending move intent. File-operation Undo/Redo remains outside scope.

Copy/Move to Other Pane context actions target the other visible browser’s current directory in the same window. Disable these actions and reject keyboard/stale requests in one-pane mode. Drag and drop targets a visible receiving browser’s current directory, including another PanePeek window. Changing layout does not redirect an already submitted operation’s captured destination under A8. Copy and move execute directly from the captured request without a routine operation-confirmation dialog. Resolve affected unsaved edits under A9 before mutation.

- **A5:** Copying a regular file or directory produces equivalent contents at the destination and leaves the source intact. Moving removes the source only after successful transfer. Directory copying preserves its nested contents; symlinks are copied/moved as links without traversing their targets.
- **A6:** Under the [same-folder copy decision](../../decisions/2026-10-22-same-folder-copies.md), copying into the source’s containing folder automatically allocates unused numbered names before the file/package extension, without a routine naming prompt. Determine folder sameness by filesystem identity, including aliases and different panes/windows. Ordinary cross-folder Copy and Move prompt only on a name collision: Keep Both suggests an unused numbered name before the file/package extension and accepts an exact edited name; Cancel aborts the batch before transfer. Regular-file collisions additionally support explicit Replace, with affected destination drafts protected and the prior destination recoverable until transfer succeeds. Folders/packages/links offer Keep Both or Cancel, without merging. Present actions horizontally as Cancel, Replace, Keep Both (omitting Replace when unavailable), with Keep Both the trailing Mauve default action and native keyboard/accessibility semantics. Reserve chosen names against existing entries and all batch destinations. Never write onto the source item. Reject same-item moves, duplicate inputs and directory transfers into themselves/descendants, resolving directory links for ancestry. Revalidate captured identities and destinations after decisions; late collisions never silently overwrite. Rejected operations preserve source/destination data.
- **A7:** Failed operations report the item, destination and actionable error. Do not report completion until filesystem work succeeds. Cross-volume moves must preserve the source if copying fails; any incomplete destination is identified and cleanup failures are reported. Do not claim multi-step transfers are transactional.
- **A8:** Transfers run away from the UI thread. Prevent duplicate submission and conflicting mutations of the same items across PanePeek windows while an operation is active; keep navigation responsive. Snapshot all sources and the destination at submission; later navigation must not redirect an in-flight transfer.
- **A9:** Resolve unsaved editor changes in every affected PanePeek window before transferring, renaming or deleting an edited file or a directory containing it. Any Cancel or failed Save aborts the requested operation before mutation. Successful moves/renames update or close affected previews; deletion closes affected previews. An editor must never silently save to an obsolete path.

### Details sidebar and preview editor

Reserve the far-right sidebar for Details, with width governed by A35. Place the selected item’s preview at the top and its filesystem metadata below. Supported text opens in read-only preview; a toggle switches this same area into an editor. File information is initially expanded and can be collapsed through an accessible disclosure. Both the chevron and the File information label toggle its state. Its preference is shared across windows and retained through selection changes and app restarts. Collapsing hides metadata fields and gives their height to the preview/editor; the selected absolute path and copy control remain outside the collapsed section. Toggling preserves preview/editor identity, draft, dirty state, caret/selection, scroll and Undo.

The primary selected item in the active pane supplies that window’s preview. Multiple selection keeps a single preview, following the most recently focused selected item; clearing selection clears the preview. Supported images and videos show a read-only media preview with collapsible File information below. Images fit the available area without distortion; video uses native playback controls and starts paused. Markdown, SVG, PDF and HTML follow A36–A39. Other directories, packages, unsupported media, oversized text, binary data and undecodable text show a clear unavailable-preview state without editing controls. The text size/encoding limits do not apply to media previews; media loading/decoding must remain bounded and responsive.

TypeScript `.ts` and `.mts` extensions, case-insensitively, take text priority over macOS video classification. The normal bounded UTF-8 rules apply; transport-stream video using these extensions is not previewed as video.

- **A42 Copy File Content:** An accessible copy icon beside Preview/Edit copies the complete current source buffer as plain text, including unsaved drafts retained in Preview. Markdown, HTML and SVG copy source markup, including front matter, without rendered formatting, line numbers, filenames or paths. Preserve Unicode, whitespace, existing line endings and trailing newlines under the loader's BOM policy. An empty buffer replaces the clipboard with an empty string. Enable copying only for loaded text belonging to the displayed primary selection; loading, unavailable and non-text previews cannot copy stale content. Readable text does not require edit access. Preserve document identity, dirty state, caret/selection, scroll, Undo, disk content and existing Command-C behaviour. Replacing a file clipboard cancels pending Cut intent. Use the existing window-local notifications for accessible success feedback and persistent dismissible write errors; report success only after the clipboard accepts the text. The icon has a 28 pt target and help/accessibility name `Copy file content`; retain compact/expanded layouts and the existing separate absolute-path copy control.

- **A10:** Preview loading is asynchronous and bounded. Rapid selection changes show only the latest requested file. Text supports UTF-8 with or without a BOM; a NUL-containing file is not text. Supported images/videos preview read-only; replacing or closing a video selection stops its playback and releases its resources. Corrupt, unavailable or unsupported media shows an honest unavailable/error state.

  When a browser list has focus, Space toggles the native Quick Look panel for its selected items in displayed order, initially showing the primary item; Escape closes it. Quick Look follows the active selection/window and handles cleared or unavailable items without stale ownership. It uses saved disk content and system-supported previews, including images, PDFs and media. Text editing, inline rename and other text fields retain their normal Space handling. Quick Look does not save/discard PanePeek drafts or change its Details text-editing contract.
- **A11:** Toggle supported text from preview to editor, retain syntax highlighting, edit it, see a dirty indicator and save explicitly. Edit shows a line-number gutter for all editable source formats, including Markdown, SVG and HTML. Number logical lines, including empty and trailing lines; wrapping does not create new source numbers. Keep numbers aligned through editing, scrolling, wrapping, text enlargement and Details resizing. Numbers remain outside document/copied bytes and keyboard editing targets, preserving input-method composition. Temporary edit locks retain the gutter; read-only and rendered previews retain their existing presentation. Highlighting changes presentation only; it must not alter file content or reset caret/selection during normal typing. Support native text selection, clipboard actions and undo.
- **A12:** Choosing another file, navigating away from the preview’s source directory or closing the window/quitting the app with edits prompts Save / Discard / Cancel. Cancel retains the current document and cancels the requested transition. Use the same adaptive native sheet presentation as transfer collisions, ordered Cancel, Discard, Save, with Save the trailing Mauve default action, Return for Save and Escape for Cancel.
- **A13:** Saving checks that the file has not changed on disk since it was loaded or last saved. Detected modification, replacement or deletion prevents an automatic overwrite and preserves the buffer. Permission/write failures also retain edits and report the failure.
- **A14:** Successful saving uses atomic replacement supported by the filesystem, preserves UTF-8 BOM presence and existing newline sequences, and does not normalise line endings. Preserve existing owner and group identities and file permissions, including executable bits and access-control lists (ACLs). Ordinary Save carries existing quarantine metadata to its staging file; sandbox Save leaves quarantine to macOS. Never clear quarantine as part of Save. Previewing a symlink may read its target, but editing it is disabled in this MVP.
- **A15:** Highlight Swift, JavaScript/TypeScript, JSX/TSX, JSON, Python, Markdown, HTML, XML, CSS, SCSS, YAML, TOML, PHP, Go, Rust, Java, Shell/Bash/Zsh, SQL, C/C++, C#, Dockerfile and Makefile in both Preview and Edit. Code languages highlight keywords, strings and comments; JSON highlights strings, literals and numbers. HTML/XML highlight tags, attributes, quoted values and comments; JSX/TSX also distinguish markup and embedded code expressions. CSS/SCSS highlight selectors, property names, values and comments; SCSS also distinguishes variables and directives. Markdown highlights headings, emphasis, links and inline/fenced code; highlighting code inside fences is optional. Markdown Edit retains source text; rendered Preview follows A36. YAML/TOML distinguish keys, strings, scalar literals and comments; YAML also distinguishes document markers and anchors/aliases, and TOML table headers. PHP also distinguishes variables and language tags. Shell highlights reserved words, quoted strings, comments, parameter references and heredocs; SQL highlights keywords, strings, quoted identifiers and comments. C/C++ and C# highlight keywords, strings and comments; C/C++ also distinguish preprocessor directives. Dockerfile distinguishes instructions, quoted values, variables and comments; Makefile distinguishes targets, directives, variables, quoted strings and comments. Unsupported extensions remain plain text. This is lexical highlighting, without language servers, code intelligence or rendering/executing content. Embedded script/style highlighting inside HTML and markup highlighting outside PHP blocks are optional.

The additional accepted file extensions are `.yaml`/`.yml`, `.toml`, `.php`, `.go`, `.rs` and `.java`. YAML/YML share one language. SCSS is supported; indented `.sass` is excluded. Use representative [YAML](https://yaml.org/spec/1.2.2/) and [TOML](https://toml.io/en/v1.0.0) syntax for configuration-file fixtures; incomplete text must remain readable.

Shell/Bash/Zsh, SQL, C/C++, C#, Dockerfile and Makefile are included through [decision 0007](../../decisions/0007-script-query-and-build-highlighting.md). Shell includes `.sh`/`.bash`/`.zsh` and common Bash/Zsh startup filenames; SQL uses `.sql`, C/C++ use common source/header extensions, and C# uses `.cs`. Dockerfile and Makefile require filename recognition as well as their accepted variants, defined by each implementation unit. Keep lexical limits visible; do not infer execution or semantic parsing.

The pre-save external-change check reduces overwrite risk but does not lock out other applications. Simultaneous external writes during saving remain a documented MVP limitation. Files are not executable content within PanePeek.

### Favourites and context menus

- **A16:** Each pane's star adds/removes its displayed directory and reflects shared favourite state across panes/windows. Toggling a star leaves navigation, selection and edit buffers unchanged. Open a favourite in the focused pane from the toolbar Favourites popover or menu-bar menu, using existing navigation and dirty guards. The popover searches folder names and full paths without changing saved order or reading the filesystem, has clear empty/no-match states and scrolling room for roughly six to eight typical rows, and provides per-row open/remove actions; the native menu-bar menu retains keyboard access to opening/removal. Remove any saved path, including unavailable paths, without opening it or changing navigation, selection or edit buffers. Explicit removal persists; repeated removal cannot add the path again. Duplicate equivalent paths are not added. Persist favourite directory paths across app launches; a missing or inaccessible favourite shows an error without being silently removed.
- **A17:** File and directory context menus offer Copy Absolute Path and Copy Relative Path. Right-clicking an unselected item selects and targets that item; right-clicking within the existing selection preserves it for selection actions and follows A12 if it replaces a dirty preview. Path-copy actions on multiple items emit one plain path per line in displayed order, without shell quoting or a `file://` prefix; preserve spaces and Unicode. Shared Copy Directory Path copies the focused pane's displayed absolute directory path using the same plain format. Rename is enabled only for one item.
- **A18:** Relative paths use the originating pane directory and preserve the displayed path rather than resolving a symlink target. Context menus also expose Duplicate, Copy to Other Pane, Move to Other Pane, Rename and Move to Trash when applicable. Duplicate copies the displayed selection into its containing folder under A6 in either browser layout, without changing clipboard contents or pending Cut intent. Reveal in Finder opens selected directories' contents and reveals/selects files, packages and file links in their containing folders, preserving listed link paths. It is also available in the File menu for keyboard access; empty selection disables it. Mixed selections apply both behaviours and detected failures remain visible without changing PanePeek documents. Group item menus as Reveal in Finder / Duplicate / Rename; Copy Absolute Path / Copy Relative Path; Copy to Other Pane / Move to Other Pane; Move to Trash, with separators between these four groups. Extra convenience actions remain UI decisions. Pane background menus expose New Text File and New Folder.

### Multiple selection and drag and drop

- **A19:** Command-click toggles individual items, Shift-click selects a range and Select All selects the visible listing. Each pane/window keeps its own selection and primary item. The interacted selected row, including a range endpoint, becomes primary. Select All retains a valid primary, otherwise choosing the first visible row. If the primary is deselected, hidden or removed, choose the first remaining selected row in displayed order; empty selection clears Details. Escape clears the focused listing.
