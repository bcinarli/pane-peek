# PanePeek MVP specification

PanePeek is a focused macOS file browser for Bilal’s local workflow. It supports one or two independent directory browsers with an inline text/image/video preview and text editor, allowing files to be inspected and moved without switching applications.

The [accepted browser UI and preview refinements](../../decisions/2026-10-16-browser-ui-and-preview-improvements.md) extend file icons, layout controls, favourites, previews and operation feedback. Their implementation and manual acceptance are tracked separately under T20.

## Requirements and proposed defaults

The product requirements below come from Bilal’s brief and spec review. Bilal accepted the current direction on 2026-10-03; details marked as proposed can still be revised through review.

| Requirement | MVP outcome |
| --- | --- |
| R1 Independent panes | Toggle one/two-browser view, preserving independent directories, selection and settings, with clickable breadcrumbs and sorting. |
| R2 File transfers | Copy or move selected items between visible panes, including drag and drop; other-pane actions require two-pane mode. |
| R3 Inline preview and editing | Inspect text/code and metadata in a resizable Details column, expandable up to half the content width; toggle Preview/Edit with syntax highlighting. |
| R4 Independent visibility | Toggle hidden files separately in each pane. |
| R5 Favourites | Save directories and open them in either pane. |
| R6 Paths and context actions | Keep the selected absolute path visible and copyable; copy absolute/relative paths from context menus and the focused directory path from shared actions. |
| R7 File management | Delete and rename items; create text files and directories. |
| R8 Windows and restoration | Use independent windows; restore the last active window’s directories, browser mode/active identity and preferred Details width on relaunch. |

Product defaults:

- Support macOS 26 and later only, using SwiftUI with an AppKit text editor and Foundation file services. iPadOS and mobile designs/builds are outside the MVP scope.
- Allow multiple windows, each with two retained directory browsers, a one/two-pane mode and resizable Details at the far right. Start new windows in two-pane mode with compact Details. The selected item’s preview is at the top of the sidebar, with file metadata below. A toggle switches supported text between preview and editor. The most recently activated pane in that window supplies the selection.
- Support multiple selection using Command-click, Shift-click and Select All. Copy to Other Pane / Move to Other Pane operate on the selection when both browsers are visible. Include drag and drop between visible panes/windows and interoperability with Finder.
- Relative paths are based on the directory displayed in the item’s pane. A file at `/example/project/src/main.swift` in a pane displaying `/example/project/src` yields `main.swift`.
- Supported images and videos have read-only previews in Details. Space opens the system Quick Look panel for selected items. Plain text and UTF-8 files up to 1 MiB are editable. The languages listed in A15 highlight in both Preview and Edit; other text stays editable without highlighting.
- Copy/Move name collisions offer editable Keep Both, Cancel and explicit regular-file Replace. Folder merging and silent overwrites are deferred; invalid or late conflicts reject safely.
- Favourites and one remembered window configuration persist locally: its ordered directory pair, browser mode, active-browser identity and preferred Details width. Relaunch restores that configuration in the initial window; the first-ever launch uses two browsers at home with compact Details. Every explicitly opened new window uses those same fresh defaults. Remember the most recently active window, not all windows. Selection, sorting, hidden-file visibility and scroll position remain session state.
- Move and Trash execute without routine operation-confirmation dialogs; affected unsaved edits still follow Save / Discard / Cancel. Delete sends items to Trash; permanent deletion is deferred. Rename targets one item at a time. New Text File and New Folder create items in the active pane’s directory.
- The development MVP is a locally built app outside the App Sandbox. Signing, notarisation and App Store distribution are deferred.

## Accepted UI design

The [Browse & peek reference and original logo](../../design/001-mvp/README.md) were accepted by Bilal on 2026-10-03. [Decision 0003](../../decisions/0003-ui-and-logo-direction.md) records the original alternatives; [the accepted layout decision](../../decisions/2026-10-11-browser-layout-modes-and-details-sizing.md) carries forward that appearance/logo direction and replaces the always-dual layout. These requirements guide native implementation:

- Offer One Pane / Two Panes as one visibly joined, mutually exclusive icon-and-text toggle in the shared toolbar, with equivalent View menu actions. One-pane mode keeps the active browser. Returning to two panes keeps that browser on the left and restores the preserved browser on the right, following A34.
- Keep Details beside the visible browser(s), with preview/editor above metadata and a visible absolute-path copy control. Its divider supports resizing; Expand / Restore is available in the Details header and View menu. Retain the compact Browse & peek default; sizing follows A35.
- Follow system appearance, using native Mac surfaces in Light and [Macchiato surfaces in Dark](../../decisions/2026-10-18-dark-macchiato-surfaces-and-controls.md): Base `#24273A` panels/previews, Mantle `#1E2030` headers/Details and Crust `#181926` frame. Retain Mauve `#C6A0F6` dark accents with Base text on enabled filled controls; Light retains darker Mauve `#8255B6` and native control presentation. Adapt editor token colours for each appearance and retain native text/caret/selection contrast.
- Browser rows use a separate muted selection fill, a contrasting outline and readable selected text, with neutral inactive selection. Retain Mauve controls. The [accepted selection decision](../../decisions/2026-10-12-muted-browser-selection.md) defines the colour roles and public native drawing approach.
- Give each pane a compact breadcrumb row: Home before filesystem root `/`, then clickable path components, with a trailing favourite star. The draft's 44 px row is a guide; native text sizing and long paths must remain accessible. Align both panes' location rows and list headings when paths wrap.
- Indicate the focused pane with a thin Mauve underline below its location, visible even without a selection. Avoid visible Active/Left/Right labels and repeated per-pane ellipsis menus. Accessible control names must still distinguish the panes and communicate focus.
- Use one shared toolbar for Go to Folder, Favourites and directory actions, targeting the most recently focused directory pane even while the editor/toolbar has keyboard focus. Go to Folder and Command-L expose an editable absolute directory path. Shared actions include parent navigation, Refresh, hidden visibility and Copy Directory Path. Sort controls remain per pane.
- Align Name | Size | Modified headings with their row columns. Name, Size and Modified are clickable sort controls. Show file sizes from listing metadata and `-` for directories or unavailable sizes; do not scan directory contents to calculate totals. Show the current direction beside the active heading; no separate sort picker or direction button.
- The toolbar Favourites button opens an anchored popover. Each saved-directory row shows its folder name above a subdued, accessible full path, with separate open-in-active-pane and remove-favourite icon buttons. Search matches folder names and full paths. Keep the header/search fixed above scrolling results, sized for roughly six to eight typical rows where space allows. No separate removal section appears in the popover.
- Show an outline star for an unsaved directory and a filled Mauve star for a saved one. Stars act on their own pane's displayed directory; opening a shared favourite acts on the focused pane. Do not add a permanent favourites column.
- Keep Copy/Move to Other Pane in file context menus and drag/drop. Do not add selection-triggered transfer buttons. Essential shared actions and context actions remain keyboard accessible.
- Keep syntax highlighting when switching supported text into Edit. The original peeking-P concept is the logo direction; production icon preparation and small-size validation remain pending.

The mockup is illustrative. Its sample files, carousel, appearance selector and preview-host reflow are design tooling. One/two-pane and Details sizing controls are product requirements under A34/A35; mockup interaction checks are not native acceptance evidence.

## Accessibility baseline

Accessibility is an app-wide requirement under the [accepted baseline decision](../../decisions/2026-10-11-native-accessibility-baseline.md). Follow Apple's [accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) and [typography](https://developer.apple.com/design/human-interface-guidelines/typography) guidance. Use applicable [WCAG 2.2 Level A and AA criteria](https://www.w3.org/TR/WCAG22/) as the baseline, interpreted for native macOS software through [WCAG2ICT](https://www.w3.org/TR/wcag2ict-22/). Accessibility takes precedence over matching the draft's exact dimensions or colours.

- Prefer system fonts and semantic text styles; retain monospaced paths/code. Support text enlargement without losing content or actions. Aim for 200%, working with native platform resizing capabilities as described by WCAG2ICT; verify the actual mechanism and any platform limits. Font styles alone do not establish enlargement support.
- Check light/dark and selected/focused states against applicable contrast requirements: 4.5:1 for normal text, 3:1 for large text and essential non-text controls/state indicators, with the standard's exceptions. Use more than colour to convey essential state.
- Make functions keyboard operable, with logical focus order, visible unobscured focus and no keyboard traps. Provide single-pointer alternatives to dragging and adequate pointer targets where the relevant native criteria apply.
- Expose useful names, roles, values and state through macOS accessibility APIs. Verify VoiceOver navigation and announcements for loading, errors and important state changes. Honour relevant system accessibility settings, including increased contrast and reduced motion.

Each UI unit checks the criteria it affects and records evidence or pending outcomes in [task evidence and MVP validation](validation.md#accessibility-and-native-review). T18 reviews all applicable A/AA criteria and records applicability, failures and remaining gaps. Native-control choices and visual approval must be accompanied by executed accessibility checks.

## Scope boundaries

The MVP includes one/two-browser layouts and Details width expansion, directory navigation with clickable breadcrumbs, per-pane name/size/modified-time sorting, refreshing, multiple selection, copying/moving and drag and drop, a details sidebar with text preview/editor and file metadata, Markdown highlighting, favourites, path copying, deletion to Trash, rename, text-file/folder creation, multiple windows and restoration of the last active window’s directory pair and layout. Regular directories and files are supported. Symlinks are listed and transferred as links; navigating through a directory link uses the canonical target location, following Finder. macOS packages are treated as files rather than browsable directories.

Excluded: iPadOS/mobile builds, cloud accounts, FTP/SFTP, remote connection management, synchronisation, search indexing, tabs, batch rename, permanent deletion, automated bulk workflows, source control integration, embedded PDF/document previews beyond the specified image/video Details previews, rendered Markdown preview, restoration of every prior window or unsaved buffers, and distribution infrastructure. Operations on a multiple-item selection are included.

Local-only means PanePeek implements filesystem operations without network clients or service connections. Paths exposed by macOS may be backed by OS-managed cloud storage or mounted volumes. The MVP does not promise offline availability or block those paths; OS failures must be surfaced. Strict volume restrictions would require a separate decision.

## User behaviour and acceptance criteria

### Directory panes

Each window owns its browsers, presentation order, one/two-pane mode, active-browser identity, preferred Details width and editor state. Each browser owns its directory, selected items, primary selected item, hidden-file setting, sort field/direction, scroll position and loading/error state. Browser identity is preserved when its displayed side changes. Shared favourites and restoration preferences belong to the application.

- **A1:** Navigate using a folder chooser, an editable absolute directory path through Go to Folder/Command-L, parent navigation, Home, clickable breadcrumbs and double-clicking a directory. Shared navigation actions target the focused pane; Home targets its own pane. Changing one pane leaves the other pane’s directory, selection and visibility unchanged. Focus remains visible with an empty selection.
- **A2:** List Name | Size | Modified columns with recognisable file-category icons. File sizes use listing metadata; directory and unavailable sizes show `-` without recursive calculation. Distinguish directories, packages and symbolic links; unknown file types use a generic file icon. Hidden items retain their type icon with a small eye-off badge, aligned row names and Hidden in their accessible description/help. Use the same hidden metadata as A4. Default to folders first and natural name order ascending. Allow sorting by name, size or last-modified time in either direction under A30. Empty directories show an empty state.

  Modified labels use completed elapsed units: under one minute Just now; under one hour minutes; under thirteen hours one through twelve hours. Thereafter use Today/Yesterday for local calendar days, otherwise `dd.MM.yyyy HH:mm` in the local timezone. Exact timestamps remain available through help/accessibility. Update relative labels each minute and after wake without rereading or reordering the listing. Unavailable metadata retains an honest fallback; future values display their exact date without special workflows.
- **A3:** An inaccessible, deleted or invalid directory produces a visible error and leaves the last successful directory usable. Slow reads do not block UI interaction; an older listing result cannot replace a newer navigation result.
- **A4:** Each pane has its own hidden-file toggle. Respect dot-prefixed names and filesystem hidden metadata. Manual Refresh reloads a pane; transfers refresh both affected panes. Automatic filesystem watching is deferred.

### Copy and move

Copy/Move to Other Pane context actions target the other visible browser’s current directory in the same window. Disable these actions and reject keyboard/stale requests in one-pane mode. Drag and drop targets a visible receiving browser’s current directory, including another PanePeek window. Changing layout does not redirect an already submitted operation’s captured destination under A8. Copy and move execute directly from the captured request without a routine operation-confirmation dialog. Resolve affected unsaved edits under A9 before mutation.

- **A5:** Copying a regular file or directory produces equivalent contents at the destination and leaves the source intact. Moving removes the source only after successful transfer. Directory copying preserves its nested contents; symlinks are copied/moved as links without traversing their targets.
- **A6:** Copy and Move prompt only on a name collision: Keep Both suggests an unused numbered name before the file/package extension and accepts an exact edited name; Cancel aborts the batch before transfer. Regular-file collisions additionally support explicit Replace, with affected destination drafts protected and the prior destination recoverable until transfer succeeds. Folders/packages/links offer Keep Both or Cancel, without merging. Present actions horizontally as Keep Both, Cancel, Replace, retaining the Mauve default action and native keyboard/accessibility semantics. Reserve chosen names against existing entries and all batch destinations. Reject same-item transfers, duplicate inputs and directory transfers into themselves/descendants, resolving directory links for ancestry. Revalidate captured identities and destinations after decisions; late collisions never silently overwrite. Rejected operations preserve source/destination data.
- **A7:** Failed operations report the item, destination and actionable error. Do not report completion until filesystem work succeeds. Cross-volume moves must preserve the source if copying fails; any incomplete destination is identified and cleanup failures are reported. Do not claim multi-step transfers are transactional.
- **A8:** Transfers run away from the UI thread. Prevent duplicate submission and conflicting mutations of the same items across PanePeek windows while an operation is active; keep navigation responsive. Snapshot all sources and the destination at submission; later navigation must not redirect an in-flight transfer.
- **A9:** Resolve unsaved editor changes in every affected PanePeek window before transferring, renaming or deleting an edited file or a directory containing it. Any Cancel or failed Save aborts the requested operation before mutation. Successful moves/renames update or close affected previews; deletion closes affected previews. An editor must never silently save to an obsolete path.

### Details sidebar and preview editor

Reserve the far-right sidebar for Details, with width governed by A35. Place the selected item’s preview at the top and its filesystem metadata below. Supported text opens in read-only preview; a toggle switches this same area into an editor. Metadata remains visible in either mode.

The primary selected item in the active pane supplies that window’s preview. Multiple selection keeps a single preview, following the most recently focused selected item; clearing selection clears the preview. Supported images and videos show a read-only media preview with metadata retained below. Images fit the available area without distortion; video uses native playback controls and starts paused. Other directories, packages, unsupported media, oversized text, binary data and undecodable text show a clear unavailable-preview state without editing controls. The text size/encoding limits do not apply to media previews; media loading/decoding must remain bounded and responsive.

- **A10:** Preview loading is asynchronous and bounded. Rapid selection changes show only the latest requested file. Text supports UTF-8 with or without a BOM; a NUL-containing file is not text. Supported images/videos preview read-only; replacing or closing a video selection stops its playback and releases its resources. Corrupt, unavailable or unsupported media shows an honest unavailable/error state.

  When a browser list has focus, Space toggles the native Quick Look panel for its selected items in displayed order, initially showing the primary item; Escape closes it. Quick Look follows the active selection/window and handles cleared or unavailable items without stale ownership. It uses saved disk content and system-supported previews, including images, PDFs and media. Text editing, inline rename and other text fields retain their normal Space handling. Quick Look does not save/discard PanePeek drafts or change its Details text-editing contract.
- **A11:** Toggle supported text from preview to editor, retain syntax highlighting, edit it, see a dirty indicator and save explicitly. Highlighting changes presentation only; it must not alter file content or reset caret/selection during normal typing. Support native text selection, clipboard actions and undo.
- **A12:** Choosing another file, navigating away from the preview’s source directory or closing the window/quitting the app with edits prompts Save / Discard / Cancel. Cancel retains the current document and cancels the requested transition.
- **A13:** Saving checks that the file has not changed on disk since it was loaded or last saved. Detected modification, replacement or deletion prevents an automatic overwrite and preserves the buffer. Permission/write failures also retain edits and report the failure.
- **A14:** Successful saving uses atomic replacement supported by the filesystem, preserves UTF-8 BOM presence and existing newline sequences, and does not normalise line endings. Preserve existing file permissions. Previewing a symlink may read its target, but editing it is disabled in this MVP.
- **A15:** Highlight Swift, JavaScript/TypeScript, JSX/TSX, JSON, Python, Markdown, HTML, XML, CSS, SCSS, YAML, TOML, PHP, Go, Rust, Java, Shell/Bash/Zsh, SQL, C/C++, C#, Dockerfile and Makefile in both Preview and Edit. Code languages highlight keywords, strings and comments; JSON highlights strings, literals and numbers. HTML/XML highlight tags, attributes, quoted values and comments; JSX/TSX also distinguish markup and embedded code expressions. CSS/SCSS highlight selectors, property names, values and comments; SCSS also distinguishes variables and directives. Markdown highlights headings, emphasis, links and inline/fenced code; highlighting code inside fences is optional. Markdown remains source text. YAML/TOML distinguish keys, strings, scalar literals and comments; YAML also distinguishes document markers and anchors/aliases, and TOML table headers. PHP also distinguishes variables and language tags. Shell highlights reserved words, quoted strings, comments, parameter references and heredocs; SQL highlights keywords, strings, quoted identifiers and comments. C/C++ and C# highlight keywords, strings and comments; C/C++ also distinguish preprocessor directives. Dockerfile distinguishes instructions, quoted values, variables and comments; Makefile distinguishes targets, directives, variables, quoted strings and comments. Unsupported extensions remain plain text. This is lexical highlighting, without language servers, code intelligence or rendering/executing content. Embedded script/style highlighting inside HTML and markup highlighting outside PHP blocks are optional.

The additional accepted file extensions are `.yaml`/`.yml`, `.toml`, `.php`, `.go`, `.rs` and `.java`. YAML/YML share one language. Bilal clarified that Sass meant SCSS; indented `.sass` is excluded. Use representative [YAML](https://yaml.org/spec/1.2.2/) and [TOML](https://toml.io/en/v1.0.0) syntax for configuration-file fixtures; incomplete text must remain readable.

Bilal accepted Shell/Bash/Zsh, SQL, C/C++, C#, Dockerfile and Makefile on 2026-10-10 through [decision 0007](../../decisions/0007-script-query-and-build-highlighting.md). Shell includes `.sh`/`.bash`/`.zsh` and common Bash/Zsh startup filenames; SQL uses `.sql`, C/C++ use common source/header extensions, and C# uses `.cs`. Dockerfile and Makefile require filename recognition as well as their accepted variants, defined by each implementation unit. Keep lexical limits visible; do not infer execution or semantic parsing.

The pre-save external-change check reduces overwrite risk but does not lock out other applications. Simultaneous external writes during saving remain a documented MVP limitation. Files are not executable content within PanePeek.

### Favourites and context menus

- **A16:** Each pane's star adds/removes its displayed directory and reflects shared favourite state across panes/windows. Toggling a star leaves navigation, selection and edit buffers unchanged. Open a favourite in the focused pane from the toolbar Favourites popover or menu-bar menu, using existing navigation and dirty guards. The popover searches folder names and full paths without changing saved order or reading the filesystem, has clear empty/no-match states and scrolling room for roughly six to eight typical rows, and provides per-row open/remove actions; the native menu-bar menu retains keyboard access to opening/removal. Remove any saved path, including unavailable paths, without opening it or changing navigation, selection or edit buffers. Explicit removal persists; repeated removal cannot add the path again. Duplicate equivalent paths are not added. Persist favourite directory paths across app launches; a missing or inaccessible favourite shows an error without being silently removed.
- **A17:** File and directory context menus offer Copy Absolute Path and Copy Relative Path. Right-clicking an unselected item selects and targets that item; right-clicking within the existing selection preserves it for selection actions and follows A12 if it replaces a dirty preview. Path-copy actions on multiple items emit one plain path per line in displayed order, without shell quoting or a `file://` prefix; preserve spaces and Unicode. Shared Copy Directory Path copies the focused pane's displayed absolute directory path using the same plain format. Rename is enabled only for one item.
- **A18:** Relative paths use the originating pane directory and preserve the displayed path rather than resolving a symlink target. Context menus also expose Copy to Other Pane, Move to Other Pane, Rename and Move to Trash when applicable. Reveal in Finder opens selected directories' contents and reveals/selects files, packages and file links in their containing folders, preserving listed link paths. It is also available in the File menu for keyboard access; empty selection disables it. Mixed selections apply both behaviours and detected failures remain visible without changing PanePeek documents. The core actions are part of the spec; final ordering, separators and extra convenience actions are UI decisions. Pane background menus expose New Text File and New Folder.

### Multiple selection and drag and drop

- **A19:** Command-click toggles individual items, Shift-click selects a range and Select All selects the visible listing. Each pane/window keeps its own selection and primary item. The interacted selected row, including a range endpoint, becomes primary. Select All retains a valid primary, otherwise choosing the first visible row. If the primary is deselected, hidden or removed, choose the first remaining selected row in displayed order; empty selection clears Details. Escape clears the focused listing. Sorting and same-directory Refresh retain surviving visible URL identities; successful navigation to a different directory clears that pane, while pending or failed navigation retains its selection. Selection changes that replace a dirty preview follow A12.
- **A20:** Transfer a selection using Copy/Move to Other Pane context actions or a drag. Preflight every item before starting. Resolve known Copy/Move name collisions under A6 before any transfer; Cancel aborts the whole batch. Unresolvable conflicts reject the whole request without mutation. During execution, stop on the first failure and report completed, failed and unattempted items. Completed transfers are not automatically rolled back.
- **A21:** Drag default: copy, with Command requesting move where PanePeek controls the destination and the source permits it. Accept local file URLs from Finder and export selected file URLs to Finder. Show the intended copy/move operation and reject unsupported payloads; do not accept service URLs. Transfers entering PanePeek obey A5–A9 and A20. Finder controls outgoing drop behaviour; resolve affected dirty buffers before starting an outgoing drag and use Refresh to reconcile later external changes.

### File management

- **A22:** Move one or more selected items to Trash directly, without a routine Trash confirmation. Resolve affected unsaved edits under A9 first; Cancel or failed Save prevents mutation. Trash symlinks themselves, not their targets; include directories and packages. On failure, report completed, failed and unattempted items. If Trash is unavailable, report an error without falling back to permanent deletion.
- **A23:** Rename one selected item inline in its browser row without changing its containing directory. Return begins rename and submits the entered filename; Escape cancels and returns list focus. Initially select the basename without its final extension, leaving the extension editable; select directory names and extensionless dotfiles whole. Context/File Rename and [file double-click](../../decisions/2026-10-12-file-double-click-rename.md) use the same inline editor; packages and file links follow the file gesture. Double-click and Command-Down open a selected directory; Return belongs to rename while the browser list is focused, following the [accepted keyboard decision](../../decisions/2026-10-12-inline-rename-and-browser-keyboard.md). Reject empty names, path separators, NUL, `.`, `..` and destination collisions. Handle case-only renames according to the filesystem’s case rules. On failure keep the original item usable and preserve affected edit buffers.
- **A24:** New Text File and New Folder prompt for a name in the active pane’s current directory. Use the same name/collision validation as rename and never overwrite an existing item. Create an empty UTF-8 text file or an empty directory, refresh affected panes and select the created item. After successful dot-prefixed creation, enable Show Hidden Files in the creating pane so the result is visible; other panes retain their visibility settings. A created text file can immediately be edited in the preview.
- **A25:** Run file mutations off the UI thread and apply A9 across windows. Refresh every open pane displaying an affected directory. If a window is browsing a directory that is moved/renamed, follow its new location when known; if it is trashed, fall back to the nearest accessible parent and explain the change. Show copy/move/Trash progress and results as compact in-window notifications without reserving a permanent bottom strip. Successful completion names the file and action (or the completed count for a batch), has no info/details action and fades after about five seconds; errors and partial failures remain until explicitly dismissed, with full outcome details accessible. A timer for an older success must not dismiss a newer notification. Announce results accessibly without stealing focus, and keep notification actions keyboard accessible.

### Multiple windows and remembered directories

- **A26:** New Window opens an independent pair of browsers at home in two-pane mode with compact Details, even when another window is browsing elsewhere. Browser mode, presentation order and Details sizing are window-local. Navigation, selection, hidden visibility and editing in one window do not change another window’s state. Favourites remain shared.
- **A27:** Persist one configuration from the most recently active window: its directory pair in presentation order (including the hidden browser), browser mode, active-browser identity, preferred Details width and expansion, browser-divider proportions, window size and screen placement. Update it after successful navigation, active-browser changes, layout/width or geometry changes and window activation; preserve it when the final window closes. Restore it in the initial launch window and when the Dock reopens the app with no browser windows open, including repeated close/reopen cycles. Command-Q relaunch and quitting after all windows close use the same record. Explicit New Window always uses A26's fresh defaults, including when no windows are open. For an unavailable remembered path, fall back to home for that browser only and show a useful message. Missing or invalid fields use corresponding safe defaults; older directory-only preferences remain usable. Persist preferred sizing before temporary clamping, apply A35 bounds, and keep the restored window within the available display area. The [restoration decision](../../decisions/2026-10-16-window-reopen-and-relaunch-restoration.md) clarifies this policy.
- **A28:** Resolve dirty buffers in all windows before quitting. Cancellation or a failed Save keeps the app open and retains pending edits. If the same file is edited in two windows, saving one causes the other to detect the changed disk version under A13; no automatic overwrite or dirty-buffer reload occurs.

The copy-first drag behaviour and single-window-configuration restoration policy are accepted defaults. Multiple windows do not imply restoration of all prior windows.

### Breadcrumbs and sorting

The [accepted sorting decision](../../decisions/2026-10-11-modified-sort-policy.md) owns the rationale for Name grouping and global Modified ordering.

- **A29:** Display a compact breadcrumb from filesystem root to the current directory at the top of each pane, preceded by Home and followed by the favourite star. Home opens the home directory; `/` remains a distinct root action. Clicking an ancestor navigates that pane to it and follows the existing unsaved-change guard. Keep all long-path components accessible, through wrapping or horizontal scrolling, and align both pane headings. Navigating through a directory symlink displays its canonical target location; parent navigation and breadcrumbs use that location, following [the Finder-style navigation decision](../../decisions/0005-finder-directory-symlink-navigation.md).
- **A30:** Each pane has independent sort controls for Name, Size and Last Modified, with ascending/descending direction. Name keeps folders first and follows the selected direction within each group. Modified sorts folders and files together by actual timestamps in either direction; timestamp ties use ascending natural name order and a stable path tie-breaker. Unknown timestamps appear last across the entire listing in either timestamp direction. Size initially sorts largest first, reverses on subsequent clicks and compares recorded byte counts numerically. Directory/package/link and unavailable sizes appear last in both directions; size ties use ascending natural names and stable paths. Sorting adds no filesystem reads or directory calculations. Sorting preserves selected item identity and does not change the other pane or window.

  Activating the current column heading reverses direction. Switching to Name starts ascending; switching to Modified starts descending (newest first). Sorting uses actual values rather than formatted date labels.

### Sidebar details and preview mode

- **A31:** Show a far-right Details sidebar per window, preview above metadata. Preview/Edit fills the remaining height after the header, controls, path and metadata, with a usable minimum preview height and scrolling when the content exceeds the available space. Use the primary selection from the active pane; empty and unsupported previews must not suppress available metadata. Directory/package selections can show metadata without a content preview. Supported image/video previews use the same available Details area, retaining metadata and read-only media controls without Preview/Edit or Save actions.
- **A32:** The Preview / Edit toggle is enabled only for editable text. Entering Edit retains the loaded content; returning to Preview retains unsaved changes and shows the current buffer read-only. The dirty indicator and Save remain available until changes are saved or explicitly discarded. Switching modes does not bypass A12 or reset the document’s undo history.
- **A33:** Show creation date, last-modified date, full Unix path, permissions in octal and symbolic form, owner and group, item type and file size when available. Keep the full selected absolute path accessible and copyable with a small adjacent control, including when content preview is unavailable. Copy the displayed item's path using A17's plain format; do not substitute a symlink target. Details are read-only. If a field is unavailable, say so rather than fabricating a value. For a symlink, show the link’s own metadata and its target path distinctly. Asynchronous details follow the latest selection; refresh after relevant saves/mutations and on manual Refresh.

### Browser layout modes and Details sizing

- **A34:** Toggle one/two-browser mode per window through the shared toolbar and View menu. One-pane mode keeps the most recently active browser, including when editor/toolbar focus is elsewhere, and preserves the hidden browser’s directory, selection/primary item, sorting, hidden-file visibility and scroll position. Returning to two panes keeps the currently visible browser on the left and restores the preserved browser on the right, even when the visible browser was formerly on the right. Retain the active browser/document throughout. Hidden controls leave keyboard/VoiceOver navigation and cannot receive shared commands or new transfers. Copy/Move to Other Pane are disabled and rejected while single; submitted operations retain their A8 snapshots. Layout changes preserve editor buffer, dirty state, caret/selection, scroll and undo without a Save / Discard / Cancel prompt; actual document changes still follow A12.
- **A35:** Resize the whole far-right Details column, including preview/editor and metadata. The compact layout remains the fresh-window default. Divider dragging and keyboard adjustment work continuously up to the smaller of half the window’s content width and the space remaining after visible browser minimums/dividers. Expand requests half-width; Restore returns to the preferred width captured before expansion. Entering Edit does not expand automatically. Recalculate bounds during dragging, window resize and browser-mode changes; retain the preferred width through temporary clamping. Keyboard adjustment starts from the actual visible width. Resizing preserves the document state covered by A34 and keeps metadata/full paths accessible. Preview/Edit height follows A31 independently of the width controls.

## Proposed architecture

Keep two production targets: `PanePeek` for the native application and `PanePeekCore` for testable filesystem and document behaviour. A core test target uses temporary directories; it must never mutate Bilal’s real files.

The shell starts with the application target. Introduce the core and its tests with meaningful behaviour, following the [accepted foundation](../../decisions/0004-swift-package-application.md).

| Surface | Responsibility |
| --- | --- |
| Application and views | Multiple-window lifecycle, browser presentation order/mode, native split sizing, pane controls, Details, prompts, commands, drag and drop and clipboard integration. |
| Pane state | Directory, selected items/primary item, hidden visibility, sorting and current listing request within one window. |
| Filesystem services | Listing, metadata, path validation, selection transfers, Trash, rename and creation, with coordination of conflicting operations across windows. |
| Details and editor state | Current item metadata, preview/edit mode, loaded document identity, original bytes, editable buffer, highlighting and save lifecycle through an AppKit bridge. |
| Local preferences | Persist shared favourites and the remembered window configuration under A27. |

Filesystem work runs off the UI thread; UI state changes return to the main actor. Avoid a generic provider layer, plugin system or remote abstraction. Exact type names and concurrency boundaries belong to the implementation unit that needs them.

A Swift package with a small app-bundling script is the accepted project foundation. An Xcode app project remains the fallback for a concrete native integration limitation: conventional bundle/signing support, at the cost of additional project configuration and a full Xcode requirement.

## Engineering and task review rules

The rules below capture the project-relevant coding, evidence and review requirements. Bilal’s core preferences remain the source for his personal collaboration rules; project continuation must not require access to his private files. PanePeek adds these task-specific constraints:

- For meaningful automated behaviour tests, use red/green TDD: write a high-value failing test, observe the intended failure, implement the smallest passing change, then refactor with the tests green. Compilation/import/setup failures do not count as the intended red result. UI layout and packaging are validated through actual app runs; do not manufacture low-value tests to imitate TDD.
- Add tests only when they protect a requirement, meaningful failure path or regression. Prefer real temporary filesystem fixtures; use bounded failure injection where the real condition cannot be reproduced reliably. No boilerplate tests, coverage targets or assertions that merely mirror implementation.
- Reuse existing functions and UI components for equivalent behaviour, especially path/name validation, file operations and prompts. Keep reuse concrete and avoid a generic abstraction that makes straightforward code harder to follow.
- Keep cognitive complexity low with clear names, local control flow and small focused functions. Do not set an arbitrary numeric threshold; review nesting, state transitions and duplication against the task’s actual risk.
- Keep comments short and limited to intent, non-obvious behaviour or a public contract. Do not narrate mechanics or add explanatory paragraphs around readable code.
- Every task produces a launchable app with visible behaviour for Bilal to test. Present the run instructions, fixture/setup steps, acceptance criteria covered and a short manual checklist. Stop for Bilal’s test and review before proceeding. A green automated suite does not substitute for that checkpoint.
- After every code unit and every other piece of work with meaningful output, run tighten followed by probe before presenting the result. These are the default review passes throughout the work.
- At milestone boundaries, consider a code-quality analysis using Bilal’s `code-quality-analysis` skill. Review its findings first; if improvement work is warranted, use the `cluster-work` skill to plan coherent remediation clusters with dependencies, validation and exit criteria. Obtain approval before implementing any cluster. Correctness issues block milestone acceptance; optional maintenance work can be deferred explicitly.
